# FT0004 — Result implicitly converted at wide-typed site

| | |
|---|---|
| **Severity** | Info |
| **Category** | FuncyTown.Analyzers |
| **Code fix** | No |

## Cause

A `Result` alias value is implicitly converted at a wide-typed site such as `object`, `dynamic`, or a non-generic `IEnumerable` element type. The alias's domain identity is lost.

## Why this matters

Aliases exist to give a domain-meaningful name to `Result<T, TError>`. Boxing them into `object` (or assigning into `var x = condition ? alias : "string"`) erases the type the rest of the system relies on.

## How to fix

Be explicit about the intent:

```csharp
// Convert before widening
object payload = result.Match(v => (object)v, e => e);

// Or terminate the chain first
int exitCode = result.Match(_ => 0, _ => 1);
```
