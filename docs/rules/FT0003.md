# FT0003 — Match over generated error union is not exhaustive

| | |
|---|---|
| **Severity** | Info |
| **Category** | FuncyTown.Analyzers |
| **Code fix** | No |

## Cause

A `Match` invocation against a generated `[ErrorUnion]` type does not cover every `[ErrorCase]`. Generated unions emit per-case `Match` overloads and a synthetic `Many` case; missing one means the match falls through.

## Why this matters

The closed-union model is the whole reason for `[ErrorUnion]` — non-exhaustive matching is a silent regression every time a new case is added.

## How to fix

Cover all cases the generator emits, including `many` for accumulated validation errors:

```csharp
string text = error.Match(
    notFound: e => e.Message,
    invalidUser: e => e.Message,
    many: e => string.Join("; ", e.Errors.Select(x => x.Message)));
```
