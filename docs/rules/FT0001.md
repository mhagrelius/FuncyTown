# FT0001 — Discarded Result return value

| | |
|---|---|
| **Severity** | Warning |
| **Category** | FuncyTown.Analyzers |
| **Code fix** | Yes |

## Cause

A method that returns a `Result<T, TError>` (or a generated alias) is invoked at statement level and the return value is dropped — neither stored, awaited, matched on, nor explicitly discarded.

```csharp
LoadUser(id); // FT0001: result is discarded
```

## Why this matters

`Result` exists so success and failure are first-class. Silently throwing the result away defeats the point: a failure becomes a no-op.

## How to fix

Pick the option that matches your intent:

```csharp
// Observe via Match
LoadUser(id).Match(_ => 0, _ => 1);

// Tap-style observation
LoadUser(id).OnFailure(LogIt);

// Store
var result = LoadUser(id);

// Explicitly discard (intent visible at the call site)
_ = LoadUser(id);

// Async: await, then store / match / discard
_ = await LoadUserAsync(id);
```

A code fix is offered to insert the explicit `_ =` discard.

## Suppression

If a particular call genuinely should drop the result, prefer the explicit `_ = …` form over a `#pragma` suppression — it's self-documenting at the call site.
