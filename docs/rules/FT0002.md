# FT0002 — Result chain crosses error types

| | |
|---|---|
| **Severity** | Info |
| **Category** | FuncyTown.Analyzers |
| **Code fix** | No |

## Cause

A chain method (`Bind`, `Then`, `AndThen`, `SelectMany`, or their async variants) is called with a continuation that produces a `Result` with a *different* `TError` than the source.

```csharp
Result<User, UserError> source = LoadUser(id);
Result<Email, EmailError> bad = source.Bind(LookUpEmail); // FT0002
```

## Why this matters

Chain methods preserve the source error type through. Silently accepting a different error type means the original failure mode disappears from the type signature, which makes diagnostics and exhaustive matching harder.

## How to fix

Convert the error explicitly first:

```csharp
Result<Email, EmailError> good = source
    .MapError(MapUserErrorToEmailError)
    .Bind(LookUpEmail);
```

Or convert the destination back at the boundary:

```csharp
Result<Email, UserError> good = source
    .Bind(user => LookUpEmail(user).MapError(MapEmailErrorToUserError));
```
