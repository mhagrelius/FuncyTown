# FT0006 — [ErrorCase] type must be sealed

| | |
|---|---|
| **Severity** | Error |
| **Category** | FuncyTown.Analyzers |
| **Code fix** | Yes |

## Cause

A type marked `[ErrorCase]` is not declared `sealed`. The generated error union relies on each case being terminal so that exhaustive matching is sound.

## Why this matters

If a case can itself be subclassed, downstream code can introduce a new error variant that the generator never sees, breaking exhaustiveness.

## How to fix

Declare the case `sealed`:

```csharp
[ErrorCase]
public sealed partial class NotFound(Guid id) : UserError
{
    public Guid Id { get; } = id;
    public override string Message => $"User '{Id}' was not found.";
}
```

A code fix is offered to insert the `sealed` modifier. The fix declines to apply itself when the type is `abstract` and has descendants — converting an abstract base into a sealed type would silently break the derived classes.
